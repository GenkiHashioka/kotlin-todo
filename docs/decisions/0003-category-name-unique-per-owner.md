# 0003 - Category名はユーザーごとに一意にする

**ステータス**: 採用
**日付**: 2026-08-01

## Context（背景・何を解決したいか）

Categoryはユーザーごとに独立して作成する（`owner_id`を持つ）。同一ユーザーが同じ名前のCategoryを複数作れてしまうと、カテゴリ一覧UIやフィルタで見分けがつかなくなる。

## Decision（何を決めたか）

`categories`テーブルに`(owner_id, name)`の複合unique制約を設定する。別ユーザー間では同じ名前のCategoryを使ってよい（例: 複数ユーザーがそれぞれ「仕事」というCategoryを持てる）が、同一ユーザー内では重複不可。

## Consequences（この決定によって何が得られ、何を犠牲にしたか）

- **得られるもの**: Category名の一意性がDB制約レベルで保証され、アプリケーションコードでの二重チェックに頼らずに済む。UI上でカテゴリ名が衝突する混乱を防げる。
- **犠牲にするもの**: Category作成時に一意性違反（`DataIntegrityViolationException`等）をハンドリングし、ユーザーにわかりやすいエラーメッセージを返す実装がPhase 4で必要になる。
