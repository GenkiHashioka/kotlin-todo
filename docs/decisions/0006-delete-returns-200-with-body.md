# 0006 - DELETE成功時は204ではなく200+削除内容を返す

**ステータス**: 採用
**日付**: 2026-08-02

## Context（背景・何を解決したいか）

DELETE成功時のレスポンス設計には、「204 No Content（ボディなし）」と「200 OK + 削除されたリソースをボディに含める」の2つの一般的な流儀がある。どちらを採用するか決める必要があった。

## Decision（何を決めたか）

`DELETE /todos/{id}`は200 OKを返し、ボディに削除されたTodoの内容（`TodoResponse`）を含める。

## Consequences（この決定によって何が得られ、何を犠牲にしたか）

- **得られるもの**: クライアントは、最終的に何が削除されたかをレスポンスから直接確認できる。
- **犠牲にするもの**: 204 No Contentという、より一般的なRESTの慣習からは外れる。削除処理のたびにレスポンスボディを組み立てるコストがわずかに発生する。
- **代替案として検討したもの**: 204 No Content。多くのAPI（GitHub APIなど）で採用されている定番だが、今回のPhase 4のチェックポイント基準（201/200/404/400の確認）に204が含まれていなかったこと、削除内容を確認できる利便性を優先し、200+ボディを採用した。
