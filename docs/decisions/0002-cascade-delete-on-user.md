# 0002 - Userを削除したら関連するTodo/CategoryもCASCADE削除する

**ステータス**: 採用
**日付**: 2026-08-01

## Context（背景・何を解決したいか）

MVPスコープにはユーザー削除機能そのものは含まれていないが、DB制約として「Userが削除された場合、そのUserが所有するTodo/Categoryをどう扱うか」は今のうちに決めておく必要がある。決めないと、外部キー制約違反でUser削除自体が失敗する、あるいは孤立したTodo/Categoryが残る、といった曖昧な状態になる。

## Decision（何を決めたか）

`todos.owner_id`、`categories.owner_id`の外部キーに`ON DELETE CASCADE`を設定する。Userが削除されたら、そのUserが所有する全てのTodo/Categoryも自動的に削除される。

## Consequences（この決定によって何が得られ、何を犠牲にしたか）

- **得られるもの**: 孤立レコード（存在しないowner_idを参照するTodo/Category）が発生しない。将来ユーザー削除機能を実装する際も、アプリケーション側で削除順序を気にする必要がない。
- **犠牲にするもの**: 誤ってUserを削除した場合、関連データが即座に失われ、取り消しが効かない（ソフトデリートではない）。運用フェーズで「うっかり削除」のリスクを許容する判断。
- **代替案として検討したもの**: `RESTRICT`（Todo/Categoryが残っている限りUser削除を禁止）。安全側だが、MVPではユーザー削除機能自体を作らないため実質的な差はなく、CASCADEの方がシンプル。
