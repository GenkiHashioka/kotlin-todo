# 0005 - 更新はPUT形式（全項目送信）とし、PATCH方式は採用しない

**ステータス**: 採用
**日付**: 2026-08-02

## Context（背景・何を解決したいか）

Todo更新APIの設計にあたり、クライアントが「変更後の全項目を毎回送る」PUT方式と、「変更したい項目だけを送る」PATCH方式のどちらを採用するか決める必要があった。

## Decision（何を決めたか）

`TodoUpdateRequest`は`title`/`priority`/`status`を必須、`description`/`dueDate`/`categoryId`を任意項目として、クライアントは更新のたびに全項目を送信するPUT方式を採用する。`id`はリクエストボディではなくURLパス（`PUT /todos/{id}`）で表現する。

## Consequences（この決定によって何が得られ、何を犠牲にしたか）

- **得られるもの**: 実装がシンプルになる。Kotlinのnullable型は「値が無い（クリアしたい）」という1通りの意味だけを持てば良く、「フィールドが送られなかった」との区別を気にする必要がない。
- **犠牲にするもの**: クライアントは一部の項目だけ変更したい場合でも、常に全項目を送る必要があり、通信量やフロントエンド側の実装コストが増える。
- **代替案として検討したもの**: PATCH方式（変更したい項目だけ送る）。「送られなかった」と「明示的にnullが送られた」をKotlinのnullable型だけでは区別できず、`JsonNullable<T>`のようなラッパー型の導入が必要になり実装が複雑化するため、学習フェーズの現段階では見送った。将来的にフロントエンド実装で必要性が出てくれば再検討する。
