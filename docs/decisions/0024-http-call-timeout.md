# 0024 - AndroidのHTTP呼び出し全体に30秒の制限時間を設ける

**ステータス**: 採用
**日付**: 2026-10-17

## Context（背景・何を解決したいか）

削除通信中の画面離脱で成功通知が失われる問題に対し、削除中の戻る操作を抑止した。一方、長時間通信が終わらないと操作を再開できない。接続・読み書きそれぞれのタイムアウトに加え、HTTP呼び出し全体の制限時間を明示する。

## Decision（何を決めたか）

ApiClientで共有OkHttpClientを構築し、callTimeoutを30秒に設定してRetrofitへ渡す。全Todo APIに適用し、接続・読み書き個別のタイムアウトは既定値を維持する。30秒は現在のTodo APIに対する設計値であり、用途が増えた場合に見直す。

通信設定をApiClientへまとめ、各ViewModelは既存の例外処理とfinallyで失敗表示・操作復帰を行う。今回はViewModelごとにCoroutineのwithTimeoutを追加しない。

## Consequences（この決定によって何が得られ、何を犠牲にしたか）

HTTP呼び出し全体の制限時間を共通設定として管理できる。登録・編集・削除だけでなく取得にも適用されるため、長時間の応答が必要なAPIを追加する場合は設定の適用範囲を再検討する。より短い接続・読み取りタイムアウトなどで先に失敗する場合もあり、常に30秒待つ設定ではない。

タイムアウトはBackendの処理失敗やロールバックを保証しない。検証ではAndroidのタイムアウト後に削除が完了した。結果不明時の再取得・整合回復とエラー文言は別途扱う。HTTPのタイムアウト設定はアプリ内の全待機処理やプロセス停止への対策ではない。
