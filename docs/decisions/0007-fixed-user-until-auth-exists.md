# 0007 - 認証機能ができるまでは固定ユーザーで代用する

**ステータス**: 採用
**日付**: 2026-08-02

## Context（背景・何を解決したいか）

Todo作成時には`owner`（`User`）が必須だが、認証機能（Phase 6で実装予定）がまだ存在しない。認証ができるまでの間、Todoのオーナーをどう決定するかを決める必要があった。

## Decision（何を決めたか）

`DevDataInitializer`（`CommandLineRunner`）が、アプリ起動時に固定のメールアドレス（`DevDataInitializer.FIXED_USER_EMAIL`）を持つユーザーを1人だけ用意する（既に存在すれば何もしない）。`TodoService`はこのメールアドレスで`UserRepository.findByEmail`を検索し、固定オーナーとして扱う。

## Consequences（この決定によって何が得られ、何を犠牲にしたか）

- **得られるもの**: 認証機能を実装せずとも、`owner`必須というドメインモデルをそのままにCRUDの実装・学習を進められる。
- **犠牲にするもの**: 固定ユーザーに関するコード（`DevDataInitializer`、`FIXED_USER_EMAIL`への参照）は、Phase 6で認証を実装した時点で丸ごと不要になり削除される、一時的なコードである。
- **代替案として検討したもの**: 先に認証機能を実装してから着手する案もあったが、20フェーズに分けた学習カリキュラムの段階的な進行方針（Phase 4はCRUD、Phase 6は認証）に反するため採用しなかった。
