# Android 08 - Todo登録・編集の保存中の戻る操作を制御する

**記録日**: 2026-10-17
**対応Issue**: [#57](https://github.com/GenkiHashioka/kotlin-todo/issues/57)
**ブランチ**: fix/android-todo-submit-navigation
**設計メモ**: [Android 08](../../design-notes/android/08-todo-submit-navigation.md)（実装前にレビュー）

## 実装結果

- 登録・編集Screenで既存のUiStateから戻る操作の可否を計算し、BackHandlerを追加した。
- 送信中と成功後の自動遷移まではシステムの戻る操作による離脱を抑止し、送信前・失敗後は戻れる。
- 編集ではLoading / LoadErrorでも戻れるようにした。
- 両画面で送信中だけ共通の「送信中…」を表示する。
- 登録の入力欄、優先度、期日の選択・解除を送信中・登録済みは無効にし、送信ボタンにも登録済みの条件を追加した。
- 両画面のタイトル判定を!isBlank()からisNotBlank()へ変更した。判定結果は同じで、条件を肯定形で読めるようにした。

既存のUiState・ViewModel・Route・NavHost・Repository・ApiClientは変更していない。画面上の戻るボタンも新設していない。

## 学びと設計理由

### 既存状態から操作の可否を求める

登録は送信中でも登録済みでもないときに戻れる。編集は入力状態以外なら戻れ、入力状態なら送信中でも更新済みでもないときに戻れる。

戻る操作の可否はローカルのvalにした。状態が変わるたびに同じ変数へ再代入するのではなく、StateFlowの変更を受けた再コンポーズで最新の入力から計算し直す。既存状態から導ける値なので、新しいフラグやrememberで二重管理しない。

### 論理演算子と状態の組み合わせ

編集の初稿では、送信中ではない、または更新済みではないというOR条件になっていた。送信中は通常まだ更新済みでないため、戻れてしまう条件だった。

必要なのは両方がfalseであることなので、括弧内をAND条件へ修正した。外側のORは、入力状態でなければ戻れるという別の条件を表す。日本語の条件と、実際のtrue / falseの組み合わせを対応させて確認した。

### BackHandlerの有効化と戻る許可は逆になる

BackHandlerは戻る操作を受け取る処理を有効にするもの。戻れないときだけ有効にし、何もせず画面離脱を抑止する。通常時は無効にしてNavigationに任せる。ユーザーの戻る操作と、NavHostからの成功後のpopBackStackを区別する。

成功済みも条件へ含めるのは、finallyで送信中が解除されてから自動遷移するまでの間も操作を防ぐため。保存失敗後は成功済みがfalseのまま送信中が解除されるので、入力を保持して操作を再開できる。

### 入力制御と送信中表示

登録フォームは送信後も入力を変更できていたが、その変更は開始時に確定した送信内容に含まれず、成功時に失われ得る。編集と同様、送信中と成功後は入力を無効にした。

操作を止める理由が分かるよう、送信中表示も追加した。フォームをLoadingへ置き換えず入力を保持する。Screenは表示・操作可否、ViewModelは既存の送信ガードと状態更新を担当する。

## 設計との差分とADR

実装はレビューした設計に沿っている。関連修正案だった登録フォームの入力制御も実装した。ロジックの変更ではない整理として、isNotBlankによるタイトル判定を採用した。

成功後の再取得通知はADR 0023、HTTPタイムアウトはADR 0024の既存方針を継続する。今回は削除で採用したScreenの戻る制御を登録・編集の既存状態へ適用したため、新規ADRは追加していない。

## 検証

### 開発者の手動確認報告

登録・編集について、提示した次の確認項目の動作確認完了が報告された。

- 送信前は戻れる。
- 送信中は進行表示が出て、入力・追加送信・戻る操作ができない。
- 成功時は自動で戻り、一覧や詳細が更新される。
- 失敗時は入力が残り、再編集・再送信・戻る操作ができる。
- 編集の初期取得中・取得失敗でも戻れる。

### Codexが行った確認

Windows側のfix/android-todo-submit-navigationブランチで、2つのScreenとstrings.xmlの差分を静的レビューした。条件式、BackHandler、既存の入力制御と送信ガード、成功後の通知・遷移との接続を確認し、git diff --checkを実行した。一時的なdelayやThread.sleepはAndroid実装内に残っておらず、共有callTimeoutは30秒のままである。

Codexはビルド・エミュレータ操作を実施していない。自動テストは追加していない。共通タイムアウトはAndroid 07で検証済みの設定を維持し、今回その実行検証は繰り返していない。連続登録・編集や削除の回帰確認は、個別の実施報告がないため手動確認済みとは断定しない。

## 残る制約と次の課題

戻る制御は、ユーザーが保存中に画面を離れる操作への対策である。アプリ終了・通信断・タイムアウト後にBackendだけ保存が完了する状況への整合回復は未対応。特に登録の再送信では重複する可能性が残る。

次は成功フィードバック（#55）、その後にパッケージ整理（#58）を扱う。結果不明時の再取得・エラー文言の見直し、自動テスト、入力復元は別途検討する。
