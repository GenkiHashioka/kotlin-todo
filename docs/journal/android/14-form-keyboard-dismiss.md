## 実装結果

設計メモの実装ステップどおり、登録画面で3つの変更を1つずつ実装・レビュー・動作確認し、最後に編集画面へ同じ変更を入れた。

| 項目 | 実装 |
|---|---|
| 余白のタップ | 入力欄を並べる縦並び（`Column`）の修飾子の先頭に、タップの検出（`pointerInput` と `detectTapGestures`）を付けた。タップされたら、フォーカスを管理する仕組み（`LocalFocusManager`）でフォーカスを外す（`clearFocus()`）。編集画面では、編集中の状態の縦並びに最大の大きさ（`fillMaxSize()`）も付けた |
| ボタン操作 | ラジオボタンの行、期日の「選択」「クリア」、確定ボタンの押したときの処理（`onClick`）の先頭で、フォーカスを外す。登録は4か所、編集は状態の行を加えた5か所 |
| タイトル欄の Enter キー | キーボードの設定（`KeyboardOptions`）で、Enter の位置の動作を「次へ（`ImeAction.Next`）」にした。押したときの処理は書かず、Compose の標準の動きで説明欄へ移る |

ViewModel と画面遷移は変えていない。送信中の無効化の条件（`enabled`）にも手を入れていない。

## 学びと設計理由

### 1行入力の Enter キーは、指定しなくても「完了」になる

Claude は当初、「Enter の位置の動作（`imeAction`）を指定しないと、押しても何も起きないことが多い」と説明した。Pixel 8 のエミュレーターで試すと、キーボードが閉じた。

1行入力（`singleLine = true`）で動作を指定しないと、Compose は「完了（`ImeAction.Done`）」として扱う。押したときの処理（`keyboardActions`）を書いていない場合の標準の動きは、キーボードだけを隠す（`keyboardController.hide()`）ことである。エミュレーターでも、閉じた後にフォーカスとカーソルがタイトル欄に残った。

この結果から、選択肢は「何も指定しない」と「完了」ではなく、「完了（現状）」と「次へ」の2つだと分かった。現状のままだと、外側のタップ（フォーカスを外す）とは閉じ方がそろわない。閉じる役は外側のタップ、Enter は次の欄へ進む役と分けるため、「次へ」を採った。

### キーボードだけ隠すのと、フォーカスを外すのは違う

キーボードを閉じる方法は2つある。

| 方法 | キーボード | フォーカスとカーソル |
|---|---|---|
| キーボードだけ隠す（`keyboardController.hide()`） | 閉じる | 入力欄に残る |
| フォーカスを外す（`focusManager.clearFocus()`） | 閉じる | 外れる |

フォーカスが残ると、入力中なのか終わったのかが見た目で分からない。今回はフォーカスを外す方法にそろえた。

### タップの検出は、子が処理したタップには反応しない

タップの検出（`detectTapGestures`）は、子のボタンやラジオボタンの行がタップを処理済み（消費）にすると反応しない。そのため、親の縦並びに付けても、余白のタップでだけ動く。スクロールのためのドラッグもタップとは判定されない。

一方、この性質のため、余白のタップだけではボタンを押してもキーボードが閉じない。人が「外側」としてタップするのは、何もない余白より次に操作したいボタンのほうが多い。そこで各ボタンの処理でもフォーカスを外した。

親が子より先にタッチを受け取る指定（`PointerEventPass.Initial`）で全部のタップを1か所で拾う案は採らなかった。入力欄の中のタップ（カーソルの移動、別の欄への移動）でもフォーカスが外れてしまうためである。実装後のエミュレーターでは、入力欄の中をタップしてもカーソルが動き、タイトル欄から説明欄へもキーボードを閉じずに移れた。

### 修飾子の順序と、縦並びの大きさでタップの範囲が決まる

タップの検出は、縦スクロール（`verticalScroll`）より前に付けた。修飾子は書いた順に外側から包むため、スクロールより前に付けると、画面いっぱいの枠に対してタップを拾える。

登録画面の縦並びは画面全体の大きさを外から受け取っていたが、編集画面の縦並びは外側の枠（`Box`）の中にあり、大きさの指定がなかった。そのままでは内容の高さしかなく、最後の項目より下の余白は枠の領域になる。設計の段階で Claude がコードを読んで気付き、最大の大きさ（`fillMaxSize()`）をタップの検出より前に付けた。

### タップの検出の中の処理は、作り直されない限り最初の値を使い続ける

タップの検出（`pointerInput(Unit)`）の中の処理は、目印の値（`key`）が変わらない限り作り直されない。そのため、中で使う値は最初に作られたときのものを使い続ける。

今回中で使うのはフォーカスの管理だけで、画面の表示中に変わらないため、目印は `Unit` でよい。送信中かどうか（`uiState.isSubmitting`）のように途中で変わる値を中で使うと、古い値を見続ける不具合になる。その場合は目印にその値を渡すか、最新の値を参照し続ける仕組み（`rememberUpdatedState`）を使う。

ボタンの押したときの処理（`onClick`）に渡す処理は、画面が描き直されるたびに新しく作られるため、この問題は起きない。

### フォーカスを外すのは、ボタンの処理の先頭にする

期日の「選択」ボタンでは、ダイアログを開く前にフォーカスを外す。開く前に外しておくと、ダイアログを閉じた後にフォーカスが戻る先の入力欄がない。設計メモで未確認にしていた「ダイアログを閉じた後にキーボードが再び開くか」は、OK・キャンセルのどちらで閉じても開かないことをエミュレーターで確かめた。

ほかのボタンも同じ順番にそろえた。ラジオボタンの行の部品（`RadioOptionRow`）の中ではなく呼び出す側に書いたのは、行を表示する部品がキーボードのことを知らないほうが役割がはっきりするためである。

## 設計との差分と採否

設計メモとの差分はない。設計メモ 6章の懸念のうち、日付選択のダイアログを閉じた後にキーボードが再び開かないことは確かめた。送信を始めて入力欄が無効になったときのフォーカスの動きは調べていないが、確定ボタンの処理で先にフォーカスを外すため、結果に影響しない。

## 検証

### 手動確認

Pixel 8 のエミュレーターで、各ステップの実装後に確認した。

| 画面 | 確認した内容 |
|---|---|
| 登録 | 見出しの横や確定ボタンの下の余白をタップすると、キーボードが閉じてカーソルも消える。キーボード表示中にドラッグしてスクロールしても閉じない |
| 登録 | 優先度の行を押すと選択が変わり、キーボードが閉じる。「選択」を押すとキーボードが閉じてダイアログが開き、OK・キャンセルのどちらで閉じてもキーボードは再び開かない。「クリア」を押すと未設定に戻り、キーボードが閉じる。確定ボタンを押すと登録されて一覧へ戻る |
| 登録 | タイトル欄の Enter の位置のキーの表示が変わり、押すとキーボードを開いたまま説明欄へ移る。説明欄の Enter は改行になる。入力欄の中をタップするとカーソルが動き、タイトル欄から説明欄へタップで移れる |
| 編集 | 登録と同じ項目に加え、保存ボタンの下の余白のタップで閉じる。状態の行を押すと選択が変わり、キーボードが閉じる。保存ボタンの下の見た目は変わらない |
| 両画面 | キーボードを出したまま全項目と確定ボタンまでスクロールできる（#65）。送信中は入力欄・ラジオボタン・ボタンが無効のまま |
| 回帰 | [Android 11 の手動回帰テスト](../../test-plans/android/11-todo-regression-testing.md)から、登録・編集の成功と Snackbar、失敗後の入力保持、送信中の戻る制御を確認した |

画面の小さいエミュレーターと横向きでは確認していない。今回は画面の配置を変えていないためである。

### コードレビュー

各ステップの差分は Claude がレビューし、修正が必要な点はなかった。任意の提案として、余白のタップの処理に意図を書いたコメントを足した。

2026-11-08に、`main`との差分をCodexでレビューした（`/codex:review`）。修正が必要な不具合は見つからず、余白のタップと各操作でのフォーカス解除、タイトル欄の「次へ」の設定は既存の責務と整合しているという結果だった。Codexはビルド・実機での確認は行っていない。設計判断が小さいため、設計判断を疑うレビュー（`/codex:adversarial-review`）は実行していない。

## 残る課題と次の作業

- 外側のタップで閉じる操作は、画面に手がかりが出ないため、知らない人は気付かない。閉じ方を増やす近道として扱い、システムの戻る操作も引き続き使える。入力欄に「閉じる」アイコンを付ける案は、入力欄の変更になるため今回は扱っていない
- 登録・編集画面の画面上の戻る操作は [#74](https://github.com/GenkiHashioka/kotlin-todo/issues/74) で扱う
