# Android 13 - Todo画面の見やすさと操作性の改善

**記録日**: 2026-11-03  
**対応Issue**: [#65](https://github.com/GenkiHashioka/kotlin-todo/issues/65)  
**ブランチ**: `feat/android-todo-ui-usability`  
**設計メモ**: [Android 13](../../design-notes/android/13-todo-ui-usability.md)（実装前にレビュー）

本書では、Composeの部品や関数を「日本語の名前（`コード上の名前`）」の形で書く。コード上の名前は、各節の初出に添える。

## 実装結果

設計メモの対象5項目を、1項目ずつ実装・レビュー・動作確認・コミットの順で進めた。

| 項目 | 実装 |
|---|---|
| 1. 一覧 | 各行をリスト項目（`ListItem`）にし、右端に矢印アイコン、行の下に区切り線（`HorizontalDivider`）を置いた。タップの処理（`clickable`）はリスト項目へ付け、行全体をタップ範囲にした。「Todoを作成」ボタンを横幅いっぱいにし、16dpの余白を付けた |
| 2. 登録・編集の配置 | 登録画面を編集画面の構成（縦スクロール（`verticalScroll`）、左右下16dpの余白、項目間12dp）に揃えた。編集画面のタイトル・説明欄に項目名（`label`）を付け、登録画面に優先度の見出しを足した。確定ボタンは両画面とも横幅いっぱいにし、登録の文言を「送信」から「登録」へ変えた。詳細の「期限」を「期日」に統一した |
| 3. ラジオボタン | 選択肢の行全体を選択可能な要素（`Modifier.selectable`、役割は`Role.RadioButton`）にし、ラジオボタン本体の押下処理は外した。選択肢のまとまりを選択グループ（`selectableGroup()`）で包んだ。優先度・状態は列挙型の定数名ではなく「低・中・高」「未着手・進行中・完了」と表示する |
| 4. タイトル | 登録・編集のタイトル欄を1行入力（`singleLine`）にした。改行（CRLF・CR・LF）を半角空白へ置き換えるタイトル整形関数（`normalizeTodoTitle`）を作り、登録・編集のViewModelの入力時と、編集の読み込み時に通す。一覧のタイトルは最大2行で末尾を「…」で省略し、詳細は全文を表示する |
| 5. キーボード表示中の到達性 | 登録・編集のスクロールする縦並び（`Column`）に、キーボードの高さ分の余白（`imePadding()`）を付けた。`MainActivity`で画面遷移の土台（NavHost）へ渡す指定に、使用済み余白の伝達（`consumeWindowInsets(innerPadding)`）を足した |

既存のCRUD、失敗後の入力保持、送信中の操作制御、成功後の再取得とSnackbarの仕組みは変えていない。ViewModelの変更は、タイトルの改行の置き換えだけである。

## 学びと設計理由

### 修飾子の順序が結果を変える場合と変えない場合

横幅いっぱい（`fillMaxWidth()`）と余白（`padding(16.dp)`）の組み合わせは、どちらの順に書いてもボタンの幅が「画面幅−左右32dp」になり、見た目は同じだった。Claudeは当初「順序で結果が変わる」と説明したが、実際に試して違いが出ないことに気付き、説明の誤りが分かった。

修飾子（`Modifier`）の順序で結果が変わるのは、背景色（`background`）やタップの処理（`clickable`）のように、描画やタップ範囲を決めるものと余白を組み合わせる場合である。タップの処理を先に書くと余白まで押せるが、余白を先に書くと余白の部分は押せない。

キーボードの高さ分の余白（`imePadding()`）も順序に意味がある。縦スクロール（`verticalScroll`）より前に付けると、スクロールの枠そのものがキーボードの上までに縮み、入力中の欄が枠の中へ自動でスクロールされる。後ろに付けると枠はキーボードの裏まで広がったままで、中身の最後に余白が足されるだけになる。

### ラジオボタン本体の押下処理を外すと、最低限のタップ範囲がなくなる

ラジオボタン（`RadioButton`）は、押下処理（`onClick`）を渡したときだけ48dpの最低限のタップ範囲を確保する。行全体を選択可能にして本体の押下処理を外したところ、ボタンが見た目の大きさ（約20dp）まで縮み、行も詰まった。

見出しと選択肢が窮屈に見えたことから原因が分かった。Claudeは事前に「48dpの範囲は残る」と説明しており、これも誤りだった。行の高さを48dp（`height(48.dp)`）に固定して解決した。公式サンプルの56dpは、選択肢が6行ある編集画面で縦に伸びすぎるため採らなかった。

### 優先度・状態の表示名は画面側の拡張関数で持つ

優先度（`Priority`）・状態（`TodoStatus`）は、通信用のモデル（`data/remote/model`）に置いた列挙型である。表示用の文字列を列挙型に持たせると、データの型が画面の文言を知ることになる。そこで画面側（`ui/todo/TodoDisplayNames.kt`）に、表示名の文字列リソースIDを返す拡張関数（`displayNameResourceId()`）を置いた。

文字列そのものではなくリソースIDを返すことで、関数を普通の関数のままにできる。文字列リソースの取得（`stringResource`）は、Composableの中でしか呼べないためである。戻り値が文字列リソースのIDであることは、注釈（`@StringRes`）で示した。

### 改行は削除せず空白に置き換える

改行を削除すると「買い物\n牛乳」が「買い物牛乳」になり、区切りが失われる。空白への置き換えなら、LF・CRでは文字数が変わらず、入力中のカーソル位置もずれない。

改行に当てはまる正規表現（`\r\n|\r|\n`）は、CRLF（`\r\n`）を先に書く。後ろに書くとCRとLFが別々に当てはまり、空白が2つになる。この点はCRLFのテストで「空白1つになる」ことを固定した。

既存データに改行があっても、編集画面の読み込み時に置き換える。1行の入力欄と、保存される値が食い違わないためである。保存しない限りデータは変わらない。

### 端まで描画する設定では、画面がキーボードの分だけ縮まない

システムバーの裏まで描画する設定（`enableEdgeToEdge()`）を使うと、Manifestの画面リサイズ指定（`adjustResize`）だけでは、キーボード表示中に画面が縮まない。編集画面で「スクロールはできるのに保存ボタンまで届かない」のはこのためだった。

キーボードの高さ分の余白（`imePadding()`）で下を空ける。画面全体の枠（`Scaffold`）が渡す余白（`innerPadding`）とキーボードの高さの両方にナビゲーションバーの分が含まれるため、使用済み余白の伝達（`consumeWindowInsets(innerPadding)`）で子の画面へ伝え、余白が二重にならないようにした。

## 設計との差分と採否

- 表示名の関数は、設計メモでは「各画面のファイルに置く」としていた。実装時に、優先度は3画面・状態は2画面で使うことが分かり、画面パッケージの1つ上（`ui/todo/TodoDisplayNames.kt`）に1つだけ置いた。共通パッケージ（`ui/todo/common`）は作っていない。共有するのは関数2つだけで、[ADR 0025](../../decisions/0025-screen-based-todo-ui-packages.md)の「共有する具体的な部品が必要になるまでcommonを作らない」の範囲で扱えると判断した。
- タイトル整形関数（`normalizeTodoTitle`）も同じ理由で同じ場所（`ui/todo/TodoTitle.kt`）に置いた。設計メモでは「ViewModelで置き換える」とだけ書いていた。
- ラジオボタンの行の高さを48dpに固定した。設計メモでは、本体の押下処理を外すと最低限のタップ範囲がなくなることを想定していなかった。
- 矢印アイコンの取り込み方は、設計メモで「実装時に決める」としていた。Material 3 1.4.0がアイコン集（`material-icons-core`）に依存していないことを確認し、Android Studioのベクター画像の取り込み機能（Vector Asset）で矢印（`ic_chevron_right`）を`res/drawable`へ取り込んだ。
- タイトルの改行の置き換えに、単体テスト（`TodoTitleTest`、4件）を追加した。設計メモでは「追加するか実装時に相談する」としていた。ViewModelごとのテストは、編集のViewModelに状態保存領域（`SavedStateHandle`）と画面遷移の引数の準備が要るため採らず、関数だけをテストした。
- 登録ボタンの文字列は、値だけでなくリソース名も`submit_button`から`create_button`へ変えた。編集画面の項目名は、既存の期日の文言と同じく画面ごとに新設した（`todo_edit_title_label`など）。

## 検証

### 手動確認

Pixel 8・Android 17.0のエミュレーターで、各項目の実装後に確認した。

| 項目 | 確認した内容 |
|---|---|
| 1 | 行のどこを押しても詳細へ進む。区切り線と矢印が出る |
| 2 | 登録・編集の余白・項目の間隔・項目名・見出しが揃い、ボタンが横幅いっぱいになる。登録画面で、ボタンを画面外へ押し出してもスクロールで届く。ボタンが「登録」、詳細の項目名が「期日」になる。登録・保存の成功とSnackbar、送信中の入力の無効化が変わらず動く |
| 3 | 選択肢の文字や行の空いた部分を押しても選べる。送信中は行を押しても選択が変わらない。登録・編集・詳細で日本語の表示名が出る。編集画面を開くと、そのTodoの優先度・状態が選ばれている。行の高さを48dpにした後、間隔が自然に見える |
| 4 | タイトル欄でEnterを押しても改行されない。説明欄からコピーした2行の文字を貼り付けると空白になる。長いタイトルは一覧で2行に省略され、詳細で全文が出る。説明欄は改行できる |
| 5 | 登録・編集でキーボードを出したまま、登録・保存ボタンまでスクロールできる。キーボードとボタンの間に不自然な隙間がなく、閉じた後に余白が残らない。横向きでも同じ操作ができる |

2026-11-03に、画面の小さいエミュレーター（Android StudioのSmall Phone：4.65インチ・720×1280、Android 17.0）で、縦向きの次の12点を確認した。確認用に、一覧で3行以上になる長いタイトルと、5行の説明を持つTodoを1件、SQLで登録した。

| 画面 | 確認した内容 |
|---|---|
| 一覧 | 区切り線と矢印がタイトルに重ならない。長いタイトルが2行で「…」になる。「Todoを作成」ボタンの文字が折り返されず、左右に余白がある |
| 登録 | キーボードを閉じた状態と出した状態の両方で「登録」ボタンまでスクロールできる。キーボード表示中に説明欄をタップしても隠れない。優先度の行を押して選べ、「期日を選択」「期日を解除」が横に並んで収まる。登録後に一覧へ戻りSnackbarが出る |
| 編集 | 説明の長いTodoで、キーボードを出したまま「保存」ボタンまでスクロールできる。優先度・状態の6行をすべて押して選べる。保存後に詳細へ戻りSnackbarが出る |
| 詳細 | 優先度・状態が日本語で表示され、「編集」「削除」ボタンが画面に収まる |

Small Phoneの横向きは確認していない。横向きはPixel 8で確認した。削除の成功・失敗と削除中の操作制御は、詳細画面の表示名を変えただけのため、今回は確認し直していない。

### 自動テスト

Windows側で`.\gradlew.bat testDebugUnitTest`を実行し、2026-11-01 21:39の結果XMLで、タイトル整形のテスト（`TodoTitleTest`）4件と既存の一覧ViewModelのテスト（`TodoListViewModelTest`）6件の計10件が成功した（失敗・エラー・スキップ0件）。XMLはClaudeが読んで確認した。

### コードレビュー

各項目の差分はClaudeがコミット前にレビューした。指摘して直したものは、編集画面の保存ボタンの横幅いっぱいの指定の漏れ、状態の選択肢のラムダ引数名（`todostatus`→`todoStatus`）、テスト関数名の付け方、1つ目のコミットでの矢印アイコンのファイルの追加漏れなどである。

2026-11-03に、`main`との差分をCodexでレビューした。通常のレビュー（`/codex:review`）では、修正が必要な不具合は見つからなかった。設計判断を疑うレビュー（`/codex:adversarial-review`）では、キーボード用の余白の計算、タイトル整形関数の置き場所、行選択の送信中の無効化、共有関数を`ui/todo`直下に置いた判断を観点として渡し、判定は承認（指摘なし）だった。Codexはどちらのレビューでも、ビルド・テスト・エミュレーターでの確認は行っていない。
