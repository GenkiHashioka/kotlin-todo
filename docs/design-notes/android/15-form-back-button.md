# 詳細設計メモ - Android 15: 登録・編集画面に画面上の戻るボタンを追加する

**バージョン**: 0.1
**作成日**: 2026-11-15
**対応Issue**: [#74](https://github.com/GenkiHashioka/kotlin-todo/issues/74)

## 1. 背景

詳細画面には画面上の「戻る」ボタンがあるが、登録・編集画面にはない。システムの戻る操作（ジェスチャーや戻るキー）を知らない人は、登録・編集画面から戻れない。#65 の確認で見つかったが、画面構成の変更になり、送信中の戻る制御（#57）にも関わるため、#65 の対象から外してこの Issue に分けた。

着手前に Claude が関連するコードを読んだ。エミュレーターではまだ確かめていない。

| 対象 | 現状 | 根拠 |
|---|---|---|
| 詳細画面の戻るボタン | 画面の縦並び（`Column`）の先頭に、文字のボタン（`Button` に「戻る」）を置いている。スクロールする内容の外にあるため、常に画面上部に見える。削除中・削除済みは無効にする | `TodoDetailScreen.kt`（Claude） |
| 詳細画面の戻る先 | 呼び出し元の画面遷移の定義（`KotlinTodoNavHost`）が、前の画面へ戻る処理（`navController.popBackStack()`）を渡している | `KotlinTodoNavHost.kt`（Claude） |
| 登録・編集画面の戻る制御 | 戻ってよいか（`canGoBack`）を画面の中で計算し、送信中・成功後は、システムの戻る操作を横取りして何もしない（`BackHandler`）。それ以外はシステムの標準の動きで前の画面へ戻る。入力途中でも確認せずに戻り、入力は破棄される | `TodoCreateScreen.kt`、`TodoEditScreen.kt`（Claude） |
| 登録画面の構成 | 画面全体が1つのスクロールする縦並びで、外側のタップでキーボードを閉じる処理（#73）もこの縦並びに付いている | `TodoCreateScreen.kt`（Claude） |
| 編集画面の構成 | 外側の縦並びの中に、残りの高さを占める枠（`Box` に `weight(1f)`）があり、読み込み中・読み込み失敗・編集中を切り替える。詳細画面と同じ形 | `TodoEditScreen.kt`（Claude） |
| 画面上部のタイトルバー | どの画面にもない。全体の枠（`Scaffold`）は `MainActivity` に1つあり、Snackbar の表示だけに使っている | `MainActivity.kt`（Claude） |
| アイコン | アイコンのライブラリ（`material-icons-core` など）は依存関係に書いていない。Material 3 から間接的に入っているかは確かめていない | `libs.versions.toml`、`app/build.gradle.kts`（Claude） |

## 2. スコープ

### この Issue で扱うもの

1. 登録・編集画面の上部に「戻る」ボタンを置き、押すと前の画面へ戻る
2. 送信中・成功後の自動遷移までは、このボタンを無効にする（システムの戻る操作と同じ条件）
3. 入力途中で押したときは、システムの戻る操作と同じく、確認せずに戻って入力を破棄する

編集画面では、読み込み中・読み込み失敗のときもボタンを表示し、押せるようにする。今のシステムの戻る操作も、この2つの状態では戻れる。

成功後の Snackbar と再取得、キーボード表示中の到達性（#65）、外側のタップでキーボードを閉じる操作（#73）を維持する。

### 今回扱わないもの

- 画面上部のタイトルバー（`TopAppBar`）の導入と、全画面の見た目の統一（3.1 で比較）
- 入力途中で戻るときの破棄確認ダイアログ
- 画面遷移の構成（`KotlinTodoNavHost` の画面の並び）の変更
- 詳細画面の戻るボタンの変更（6章の連打の確認で問題が見つかった場合は、扱いを相談する）
- 登録・編集画面の共通フォーム化

## 3. 設計方針

### 3.1 部品：詳細画面と同じ「戻る」ボタンを、同じ位置に置く

登録・編集画面の上部に、詳細画面と同じ文字のボタン（`Button` に「戻る」）を置く。文字は既存の文字列（`R.string.back`）を使う。

| 案 | 判断 |
|---|---|
| 詳細画面と同じ「戻る」ボタンを、登録・編集画面に置く | 採用。3画面の戻る操作の見た目と位置が揃う。新しい部品やライブラリを追加せず、Issue の範囲（2画面）に収まる |
| 登録・編集画面にだけタイトルバー（`TopAppBar`）と矢印アイコンを入れる | 不採用。Android で一般的な見た目になるが、詳細画面だけ文字のボタンのまま残り、3画面で戻る操作の見た目が揃わない |
| 全画面にタイトルバーを入れる | 今回は不採用。見た目は最も整うが、一覧・詳細を含む全画面の構成変更になり、Issue が対象外とする「全画面のデザイン刷新」に当たる。アイコンのライブラリを追加するかの判断も要る。#74 の後に README のスクリーンショットを先に載せ、タイトルバーは別 Issue で扱う。導入後にスクリーンショットを撮り直す |

### 3.2 ボタンを置く位置：スクロールする内容の外

ボタンは、スクロールする入力欄の並びの外（上）に置き、スクロールしても常に見えるようにする。詳細画面と同じ形である。

**編集画面**は、既に詳細画面と同じ「外側の縦並び＋残りの高さを占める枠」の形なので、外側の縦並びの先頭にボタンを足すだけでよい。

```kotlin
Column(modifier = modifier) {
    Button(
        onClick = onBack,
        enabled = canGoBack,
    ) {
        Text(text = stringResource(R.string.back))
    }

    Box(
        modifier = Modifier
            .fillMaxWidth()
            .weight(1f),
    ) {
        when (uiState) { ... }  // 今のまま
    }
}
```

**登録画面**は画面全体が1つのスクロールする縦並びなので、外側に縦並びを1つ足し、今の縦並びを残りの高さを占める形（`weight(1f)`）で中に入れる。外側のタップ（`pointerInput`）・キーボード分の余白（`imePadding`）・スクロール（`verticalScroll`）は、今の縦並びに付けたままにする。

```kotlin
Column(modifier = modifier) {
    Button(
        onClick = onBack,
        enabled = canGoBack,
    ) {
        Text(text = stringResource(R.string.back))
    }

    Column(
        modifier = Modifier
            .fillMaxWidth()
            .weight(1f)
            .pointerInput(Unit) { ... }  // 今のまま
            .imePadding()
            .verticalScroll(rememberScrollState())
            .padding(...),
        verticalArrangement = Arrangement.spacedBy(12.dp),
    ) {
        // 入力欄・選択肢・確定ボタン（今のまま）
    }
}
```

| 案 | 判断 |
|---|---|
| スクロールする内容の外（上）に置く | 採用。下までスクロールしても、キーボードを出したままでも、戻るボタンが見える。詳細画面と同じ |
| スクロールする縦並びの先頭に置く | 不採用。変更は1行で済むが、下へスクロールするとボタンが画面外に出る |
| 確定ボタンの横に「キャンセル」として置く | 不採用。下までスクロールしないと見えず、Issue の「画面上の戻る操作」にならない |

ボタンの左右の余白は、詳細画面に合わせて付けない。3画面とも余白がない状態を揃えて見直したい場合は、全画面の見た目の課題として別に扱う。

### 3.3 戻ってよいかの条件：既存の `canGoBack` をボタンと共有する

ボタンの有効・無効（`enabled`）には、システムの戻る操作の横取り（`BackHandler`）と同じ `canGoBack` を使う。条件を1か所で計算するため、2つの戻る操作の条件がずれない。

| 画面 | 戻れる状態 | 戻れない状態 |
|---|---|---|
| 登録 | 入力中、登録失敗後 | 送信中（`isSubmitting`）、登録済み（`isCreated`） |
| 編集 | 読み込み中、読み込み失敗、入力中、保存失敗後 | 送信中（`isSubmitting`）、保存済み（`isUpdated`） |

| 案 | 判断 |
|---|---|
| 画面で計算している `canGoBack` を、ボタンと `BackHandler` で共有する | 採用。詳細画面と同じ形で、条件が1か所にまとまる |
| ViewModel の UI State に「戻ってよいか」を持たせる | 不採用。今は送信中・成功後の2つのフラグから決まるだけで、画面での計算で足りる。単体テストで確かめたくなった時点で検討する |

送信中・成功後に無効のボタンを表示するか隠すかは、詳細画面に合わせて「無効で表示」にする。隠すと、送信の開始や成功の瞬間にボタンが消えて、下の内容の位置がずれる。

### 3.4 戻る処理の渡し方：画面遷移の定義から `onBack` を渡す

戻る処理は、詳細画面と同じく、画面遷移の定義（`KotlinTodoNavHost`）から渡す。画面は「戻りたい」と伝えるだけで、どこへ戻るかは知らない。

```text
KotlinTodoNavHost  onBack = { navController.popBackStack() }
  └─ TodoCreateRoute / TodoEditRoute  onBack を受け取り、そのまま渡す
       └─ TodoCreateScreen / TodoEditScreen  ボタンの onClick = onBack
```

| 案 | 判断 |
|---|---|
| 呼び出し元から `onBack` を渡し、`popBackStack()` を呼ぶ | 採用。詳細画面と同じ形。画面は画面遷移の仕組み（`NavController`）を知らずに済み、プレビューやテストで差し替えられる |
| システムの戻る操作と同じ処理を呼ぶ（`OnBackPressedDispatcher.onBackPressed()`） | 不採用。ボタンを押すと、無効にしているはずの `BackHandler` ではなく、別の経路をたどる。無効時の動きは `enabled` で止まるので結果は同じになるが、詳細画面と書き方がずれる |
| 画面の中で `NavController` を受け取って戻る | 不採用。画面が画面遷移の仕組みに依存し、[architecture.md](../../architecture.md) の層の責務から外れる |

`popBackStack()` は、システムの戻る操作と同じく、入力内容を保存せずに前の画面へ戻る。入力途中の扱いは今と一致する。

## 5. 確認方法

以下は確認予定であり、実施済みではない。エミュレーターでの確認、Claude によるコード・テストレポートの確認、Codex のレビューを区別して journal へ記録する。

### 手動確認

登録・編集の両画面で行う。

- 表示：画面上部に「戻る」ボタンがあり、詳細画面と同じ位置・見た目である
- 戻る：入力前・入力途中に押すと前の画面へ戻る（登録は一覧、編集は詳細）。入力途中の内容は残らず、もう一度開くと初期状態である（システムの戻る操作と同じ）
- 送信中：ボタンが無効になり、押しても戻らない。システムの戻る操作も今までどおり戻らない
- 成功後：成功すると自動で戻り、Snackbar が出て、一覧（編集では詳細も）が再取得される。自動遷移までの間に戻るボタンを押しても二重に戻らない
- 失敗後：登録・保存の失敗後はボタンが有効に戻り、押すと戻れる
- 編集の読み込み：読み込み中・読み込み失敗の状態でもボタンが表示され、押すと詳細へ戻れる
- スクロール：下までスクロールしても、キーボードを出したままでも、ボタンが見える。全項目と確定ボタンに届く（#65）
- キーボード：入力欄の外側の余白をタップするとキーボードが閉じる（#73）。キーボード表示中に戻るボタンを押すと、戻った先の画面でキーボードが残らない
- 連打：戻るボタンを素早く2回押しても、一覧まで戻りすぎたり、画面が空になったりしない（6章）
- 回帰：[Android 11 の手動回帰テスト](../../test-plans/android/11-todo-regression-testing.md)から、登録・編集の成功と Snackbar、失敗後の入力保持、送信中の戻る制御のケースを再確認する

### 自動テスト

- `testDebugUnitTest` の既存テストが成功する。今回は画面側（Composable）と画面遷移の定義だけの変更で、ViewModel は変えないため、単体テストは追加しない

## 6. 想定される詰まりポイント

- **連打で2回戻る**：`popBackStack()` は呼ばれた回数だけ戻る。戻るボタンを素早く2回押すと、画面が切り替わるアニメーションの間にもう一度呼ばれ、登録画面から一覧を越えて戻り、画面が空になる可能性がある。詳細画面の既存のボタンにも同じ可能性があるが、確かめていない。まずエミュレーターで確かめ、起きた場合は、画面が操作を受け付けている状態（`RESUMED`）のときだけ処理を通す仕組み（Lifecycle の `dropUnlessResumed`）で包む案を検討する。詳細画面に同じ対処を入れるかは、その時点で相談する
- **登録画面の組み替えでタップの範囲が変わる**：今の縦並びを残りの高さを占める形（`weight(1f)`）にしないと、内容の高さしかなくなり、最後の項目より下の余白をタップしてもキーボードが閉じない（#73 の編集画面と同じ注意）
- **キーボード分の余白の付け方**：キーボード分の余白（`imePadding`）は、今と同じくスクロールする縦並びに付ける。外側の縦並びに付けると、戻るボタンを含む画面全体が押し上げられる可能性がある
- **戻った後のキーボード**：入力欄にフォーカス（入力を受け付けている状態）がある状態で画面を離れたとき、キーボードが自動で閉じるかは確かめていない。残る場合は、ボタンを押したときにフォーカスを外す処理（`focusManager.clearFocus()`）を先に呼ぶ
- **引数の追加漏れ**：`onBack` を `TodoCreateRoute` / `TodoEditRoute` と画面の両方に足す。プレビュー（`@Preview`）で画面を呼んでいる箇所があれば、そちらにも引数を足す
