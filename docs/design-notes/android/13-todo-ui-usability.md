# 詳細設計メモ - Android 13: Todo画面の見やすさと操作性を改善する

**バージョン**: 0.1
**作成日**: 2026-10-31
**対応Issue**: [#65](https://github.com/GenkiHashioka/kotlin-todo/issues/65)

## 1. 背景

Todo CRUD、手動回帰テスト（#62）、一覧ViewModelの単体テスト（#63）が揃った。次は既存機能を使いやすくするUI・操作性の改善を一区切りとして行う。改善項目は、実際に使っていて困った点から挙げた。

着手前にClaudeが現行の4画面のコードを読み、その結果をエミュレーターで確かめた。

| 対象 | 現状 | 根拠 |
|---|---|---|
| 一覧 | 各行は`Text`に`clickable`と余白を付けただけで、区切り線・矢印がない。タップできることが見た目から分からない | コード（Claude） |
| 登録・編集の配置 | 登録画面は余白・項目間隔なし。編集画面はタイトル・説明欄にlabelがなく、どちらの欄か判別できない。登録画面は「優先度」の見出しがない。確定ボタンは登録「送信」、編集「保存」 | コード（Claude） |
| ラジオボタン | `onClick`が`RadioButton`本体だけにあり、文字を押しても選べない | コード（Claude）、エミュレーター |
| タイトル | `singleLine`がなく改行できる。一覧・詳細は`maxLines`がなく全文が折り返される | コード（Claude）、エミュレーター（改行を入力できた） |
| 登録画面の到達性 | `verticalScroll`がなく、改行でボタンを画面外へ押し出すとスクロールできない | エミュレーター |
| 編集画面の到達性 | スクロールはできるが、キーボードに隠れた「保存」ボタンまで届かない | エミュレーター |

`MainActivity`は`enableEdgeToEdge()`（システムバーの裏まで描画する設定）を使い、Manifestは`adjustResize`である。edge-to-edgeでは画面がキーボードの分だけ自動で縮まないため、`adjustResize`だけではキーボード表示中の領域が確保されない。編集画面で届かない原因はこれと考える。

関連文書: [要件](../../requirements.md)、[基本設計](../../architecture.md)、[ロードマップ](../../roadmap.md)、[ADR 0025: 画面別のTodo UIパッケージ](../../decisions/0025-screen-based-todo-ui-packages.md)、[Android 11: 手動回帰テスト](../../test-plans/android/11-todo-regression-testing.md)。

## 2. スコープ

### この改善で扱うもの

1. 一覧の項目がタップできると分かる見た目
2. 登録・編集の余白・項目名・配置の統一
3. 優先度・状態のラジオボタンを、文字を含む行全体で選べるようにする
4. タイトルの1行入力と、長いタイトル・改行の入力と表示の方針
5. 小さい画面とキーボード表示中に、登録・編集の全項目と確定ボタンへ到達できる

既存のCRUD、失敗後の入力保持、送信・削除中の操作制御、成功後の再取得とSnackbarを維持する。

### 今回扱わないもの

一覧のソート、新しいTodo機能、結果不明時の整合回復、Backend変更、全面的なデザイン刷新、DIライブラリ導入、マルチモジュール化、全画面の自動テスト化、登録・編集画面の共通フォーム化。

次の2点は別Issueへ分ける（理由は下の表）。

- キーボードの外側をタップして閉じる操作
- 登録・編集画面の画面上の「戻る」ボタン（TopAppBar）

### 着手前に扱いを決めた気付き

確認中に見つかった、Issueの対象5項目に含まれない点である。着手前に、今回へ含めるか別Issueへ分けるかを次のとおり決めた。

| 気付き | 困る場面 | 対象との関係 | 決定 |
|---|---|---|---|
| キーボードの外側をタップしても閉じない | 入力後に下の項目を見たいとき、戻る操作でしか閉じられない | 5（キーボード表示中の到達性） | 別Issue。5でスクロールと余白を直せば、開いたままでも下の項目へ届く。閉じ方はAndroid標準の戻る操作もあり、到達できない問題ではない |
| 優先度・状態が`LOW`・`TODO`などのenum名（列挙型の定数名）のまま表示される | 日本語の画面に英語の定数名が混ざる | 2（項目名）・3（ラジオボタン） | 今回へ含める。3でラジオボタンの行を作り直すため、表示文字列を差し替える場所が同じになる。詳細画面の表示も合わせる |
| 詳細は「期限」、登録・編集は「期日」と呼び名が違う | 同じ項目が画面で別の名前に見える | 2（項目名） | 今回へ含める。strings.xmlの変更だけで済む |
| 登録・編集画面には画面上の「戻る」ボタンがない | 戻る操作を知らない利用者が戻れない | 2（配置） | 別Issue。TopAppBar（画面上部のタイトルバー）の導入を含む画面構成の変更になり、送信中の戻る制御にも関わる |
| 一覧の「Todoを作成」ボタンに横の余白がない | 画面端に寄って見える | 1（一覧の見た目） | 今回へ含める。余白の追加だけに留め、FAB（画面右下に浮かぶ丸いボタン）への置き換えはしない |

## 3. 設計方針

### 3.1 実装の順序

挙げた順（1→5）で進める。ただし、5の登録画面のスクロール追加は2と同じ箇所を変えるため、2と同時に行う。

| 順 | 内容 | 主な変更ファイル |
|---|---|---|
| 1 | 一覧の見た目 | `TodoListScreen.kt` |
| 2 | 登録・編集の配置と項目名、登録画面のスクロール | `TodoCreateScreen.kt`、`TodoEditScreen.kt`、`strings.xml` |
| 3 | ラジオボタンの行選択と表示名 | `TodoCreateScreen.kt`、`TodoEditScreen.kt`、`TodoDetailScreen.kt`、`strings.xml` |
| 4 | タイトルの1行入力と表示 | 登録・編集のScreenとViewModel、`TodoListScreen.kt` |
| 5 | キーボード表示中の到達性 | `MainActivity.kt`、登録・編集のScreen |

5を最初に行う案は採らなかった。最も困る問題ではあるが、2で登録画面の骨組み（余白・スクロール）を作り直すため、5を先に行うと同じ箇所を2回変えることになる。キーボードの扱いは2で骨組みが揃ってから入れるほうが、変更の理由を分けて説明できる。

1つの項目ごとに実装し、Claudeのコードレビューとエミュレーターでの動作確認をしてから次へ進む。コミットも項目ごとに分ける。

### 3.2 一覧：ListItemと区切り線と矢印

各行をMaterial 3の`ListItem`にし、行の間に`HorizontalDivider`（区切り線）を入れる。行の右端に右向きの矢印アイコン（›）を置き、「押すと先へ進む」ことを示す。

| 案 | 判断 |
|---|---|
| `ListItem` + 区切り線 + 右矢印 | 採用。Material 3の一覧の標準的な形で、タップで先へ進む行であることが伝わる |
| `Card`で行を囲む | 不採用。見た目の変化が大きく、全面的なデザイン刷新に近づく |
| 区切り線だけを足す | 不採用。行の境目は分かるが、押せることは伝わらない |

`ListItem`の`headlineContent`にタイトルを置き、`trailingContent`に矢印を置く。`clickable`は`ListItem`の`modifier`へ付け、行全体をタップ領域にする。

「Todoを作成」ボタンは位置を変えず、横幅いっぱいにして左右に余白を付ける。

### 3.3 登録・編集：編集画面の構成に揃える

登録画面を、既に余白とスクロールがある編集画面の構成へ揃える。

- 外側の`Column`に`verticalScroll`、左右下16dpの余白、項目間12dpの間隔を付ける。
- タイトル・説明の入力欄は両画面とも`label`を付け、横幅いっぱいにする。
- 優先度・状態・期日の前に見出しの`Text`を置く。
- 確定ボタンは登録「登録」、編集「保存」とし、横幅いっぱいにして最後に置く。送信中表示とエラー表示はボタンの下に置く。
- 期日の呼び名を「期日」に統一する（詳細画面の「期限」を変える）。

確定ボタンを両画面で同じ文言にする案は採らなかった。新しく作る操作と、既存を書き換える操作は別のものであり、文言で区別できるほうが分かりやすい。「送信」はAPIへ送る仕組みを表す言葉で、利用者にとっての操作の意味を表していないため変える。

登録と編集のフォームを1つの共通Composableにまとめる案は今回採らない。編集画面には読み込み中・読み込み失敗と状態の項目があり、違いを引数で吸収する設計が必要になる。共通化は別の問題として判断する。

### 3.4 ラジオボタン：行全体をselectableにする

選択肢の行（`Row`）に`Modifier.selectable`を付け、行全体を1つの選択肢にする。`RadioButton`の`onClick`は`null`にし、タップの処理を行に一本化する。選択肢を並べる親の`Column`には`Modifier.selectableGroup()`を付ける。

```text
Column(selectableGroup)
  └ Row(selectable: selected / enabled / role = RadioButton / onClick)
       ├ RadioButton(onClick = null)
       └ Text(表示名)
```

- `selectable`の`enabled`に既存の送信中・送信済みの条件を渡し、送信中の無効化を維持する。
- `role = Role.RadioButton`で、TalkBack（画面読み上げ機能）が行をラジオボタンとして読み上げる。
- `RadioButton`にも`onClick`を残すと、本体を押したときと行を押したときでタップの処理が2か所になるため、`null`にする。

| 案 | 判断 |
|---|---|
| 行に`selectable`、`RadioButton`は`onClick = null` | 採用。Composeの公式ガイドが示す形で、読み上げの単位も行になる |
| `Text`にも`clickable`を付ける | 不採用。タップの処理が2か所に分かれ、行の余白部分は押せないまま残る |

行の部品はそれぞれのScreenファイル内の`private`なComposableとして書く。共通パッケージ（`ui/todo/common`）は作らない。ADR 0025の「共有する具体的な部品が必要になるまでcommonを追加しない」に照らすと、今回の行は数行の部品で、登録・編集の2ファイルに収まるためである。

表示名はenum名をそのまま使わず、strings.xmlの日本語を使う。enumの値から文字列リソースを選ぶ関数を、Screen側に置く。enum（`data/remote/model`）に表示用の文字列を持たせない。データの型が画面の文言を知ることになるためである。

### 3.5 タイトル：入力は1行、改行は空白に置き換える

| 場面 | 方針 |
|---|---|
| 登録・編集の入力欄 | `singleLine = true`にする。Enterで改行が入らない |
| 貼り付けで改行が入る場合 | ViewModelのタイトル更新処理で、改行（`\r\n`・`\r`・`\n`）を半角空白に置き換える |
| 既存データに改行がある場合 | 編集画面へ読み込むときに同じ置き換えを行う。保存すると改行のないタイトルになる |
| 一覧の表示 | 最大2行、超えた分は末尾を「…」で省略する |
| 詳細の表示 | 全文を折り返して表示する |

`singleLine`はEnterキーによる改行を止めるが、貼り付けた文字列に含まれる改行までは取り除かない可能性がある。そのため、入力値を受け取るViewModel側でも置き換える。

改行を削除する案は採らなかった。「買い物\n牛乳」が「買い物牛乳」になり、区切りが失われる。

既存データを読み込み時にも置き換えるのは、1行の入力欄に改行が残ると表示と保存される値が食い違うためである。編集で保存しない限りデータは変わらない。説明は今後も複数行の入力を許す。

一覧を1行で省略する案は採らなかった。短い画面幅では多くのタイトルが途中で切れ、行の区別が付きにくい。

### 3.6 キーボード表示中の到達性：imePaddingを入力画面に付ける

登録・編集のスクロールする`Column`に`Modifier.imePadding()`を付け、キーボードの高さ分の余白を下に足す。これにより、キーボードの上まで確定ボタンをスクロールできる。

`MainActivity`のScaffoldが渡す`innerPadding`はナビゲーションバーの高さを含む。キーボードの高さもナビゲーションバーの分を含むため、そのまま`imePadding`を足すとナビゲーションバーの分だけ余白が二重になる。NavHostへ渡すModifierで`padding(innerPadding)`の後に`consumeWindowInsets(innerPadding)`を付け、既に余白として使った分を下の画面へ伝える。

| 案 | 判断 |
|---|---|
| 入力画面に`imePadding`、`MainActivity`で`consumeWindowInsets` | 採用。キーボードが関わる画面だけが変わり、一覧・詳細とSnackbarの位置は変わらない |
| Scaffoldの`contentWindowInsets`にキーボードを含める | 不採用。全画面の余白がキーボードに合わせて変わり、Snackbarの表示位置にも影響する |
| `enableEdgeToEdge`をやめる | 不採用。Android 15以降を対象にするとedge-to-edgeが既定になり、解決にならない |

## 4. 実装ステップ

1. この設計メモをレビューし、「着手前に扱いを決めた気付き」の扱いを決める。
2. 一覧を`ListItem`・区切り線・矢印にする。矢印はVector Assetで取り込む（6章）。「Todoを作成」ボタンに左右の余白を付ける。
3. 登録画面を編集画面の構成に揃え、両画面の項目名・見出し・確定ボタンを整える。期日の呼び名を統一する。
4. ラジオボタンの行選択と表示名を、登録の優先度、編集の優先度・状態、詳細の表示へ反映する。
5. タイトルを1行入力にし、ViewModelで改行を置き換える。一覧の表示を2行で省略する。
6. 登録・編集に`imePadding`を付け、`MainActivity`に`consumeWindowInsets`を付ける。
7. 5章の確認を行い、結果を記録する。
8. journalを作成し、README、文書一覧、基本設計、要件、ロードマップと関連ADRを必要に応じて更新する。
9. `/codex:review`と`/codex:adversarial-review`を実行し、指摘の採否を決めてから、コミット・push・PR作成へ進む。

各ステップでは、使うComposeのModifierや部品の役割を実際のコードと結び付けて説明し、完成コードを一括で提示しない。

## 5. 確認方法

以下は確認予定であり、実施済みではない。エミュレーターでの確認、Claudeによるコード・テストレポートの確認、Codexのレビューを区別してjournalへ記録する。

### 手動確認

- 一覧：各行に区切り線と矢印があり、行のどこを押しても詳細へ進む。
- 登録・編集：両画面とも余白・項目名・見出しが揃い、入力欄がどの項目か分かる。
- ラジオボタン：文字や行の余白を押しても選べる。送信中は行を押しても選択が変わらない。表示名が日本語になっている。
- タイトル：Enterで改行されない。改行を含む文字列を貼り付けると空白に置き換わる。長いタイトルは一覧で2行に省略され、詳細では全文が出る。
- 到達性：登録・編集でキーボードを出したまま、全項目と確定ボタンまでスクロールできる。キーボードを閉じたとき、下に不要な余白が残らない。
- 小さい画面：画面の小さいエミュレーター（または横向き）で、上と同じ操作ができる。
- 回帰：[Android 11の手動回帰テスト](../../test-plans/android/11-todo-regression-testing.md)から、登録・編集・削除の成功とSnackbar、失敗後の入力保持、送信・削除中の戻る制御のケースを再確認する。

### 自動テスト

- `testDebugUnitTest`の既存6件が成功する。
- タイトルの改行置き換えはViewModelの処理になるため、単体テストを追加するかを実装時に相談する。#63と同じFakeを使えば小さく書ける。

## 6. 想定される詰まりポイント

- 矢印アイコンは`Icons`（`material-icons-core`）では使えない。現在使っているMaterial 3 1.4.0は`material-icons-core`に依存しておらず、Gradleのキャッシュにも入っていない（2026-10-31にClaudeが確認）。Android StudioのVector Assetで`chevron_right`を`res/drawable`へ取り込み、`painterResource`で表示する。`material-icons-core`を依存に足す案は採らない。Googleが更新を止めており、Material 3も依存から外したためである
- `Modifier.selectable`と`RadioButton`の`onClick`を両方残すと、タップが2か所で処理される。`RadioButton`は`onClick = null`にする。
- `selectable`の`enabled`を渡し忘れると、送信中も行を押して選択を変えられてしまう。
- `verticalScroll`を付けた`Column`の中に`weight`や`fillMaxHeight`を使うと、高さが決まらず実行時エラーになる。
- `imePadding`の付け方を誤ると、ナビゲーションバー分の余白が二重になるか、キーボードを閉じた後に余白が残る。`consumeWindowInsets`の位置は`padding(innerPadding)`の後にする。
- 改行の置き換えをScreen側で行うと、ViewModelのテストで確かめられない。入力値の変換はViewModelに置く。
- 改行を置き換えた後のカーソル位置がずれる可能性がある。現在は`String`で値を受け取っているため、貼り付け時の挙動を確認する。
- 表示名の関数で`stringResource`を使う場合はComposableにする。通常の関数からは呼べない。
