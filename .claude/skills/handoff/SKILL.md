# 引き継ぎを書く

次のセッションの Claude が、この会話を読まずに作業を再開できるようにする。

## 手順

1. 作業中のブランチを確認する。WSL 側クローンと Windows 側クローン（`/mnt/c/Users/gensh/projects/kotlin-todo`）の両方を見て、`main` でない方を対象にする。両方とも `main` なら、開発者にどのブランチの引き継ぎかを聞く
2. ファイル名はブランチ名の `/` を `-` に置き換えたもの。保存先は WSL 側クローンの `.claude/handoff/<ファイル名>.md`。既にあれば上書きする（追記しない）
3. 下の形式で書く。会話に無いことは書かない。推測は「要確認」と明記する
4. 書いた内容を開発者に見せ、次に `/clear` を実行してよいことを伝える

## 形式

```markdown
# <Issue 番号とタイトル>

更新: <YYYY-MM-DD>
ブランチ: <ブランチ名>（<WSL 側 / Windows 側>）

## 目的
<この Issue で達成すること。1〜2 行>

## 決めたこと
- <決定>：<理由>。却下した案：<案と理由>

## 状態
- 実装済み / 動作確認済み / 本人が説明済み / 要確認 を区別して書く

## 未解決
- <まだ決めていないこと、詰まっている点>

## 次の一手
- <次のセッションで最初にやること。誰がやるか>

## 関連ファイル
- <design-note / journal / 触ったコードのパス>
```

## 書かないこと

- 会話の経緯そのもの（結論と理由だけ残す）
- design-note・journal・ADR に既に書いた内容（リンクで示す）
